# 運用ルール

## 毎朝の実行順序

`/daily` で、以下の順番で実行する。
(「毎朝8時」に自動で動かすには cron などの別の仕組みが要る。README を参照)

1. researcher サブエージェントで、`inputs/asp/` から案件を最大10件抽出
　→ `output/research/<日付>.md` に保存

2. planner サブエージェントで、設計図を3本作成
　→ `output/plan/<日付>.md` に保存

3. writer サブエージェントで、記事を1本作成
　→ `output/draft/<日付>.md` に保存

4. 機械チェック `node scripts/check.mjs` を実行してから、checker サブエージェントで記事を判定
　→ 判定が「要修正」なら、執筆担当に差し戻して再度3〜4を実行
　→ 判定が「公開可」なら `output/final/<日付>.md` に保存
　→ 判定が「人間確認」なら、理由を `output/check/` に残し、最後の報告で知らせる

5. 完了したら「本日の記事1本、確認待ち」と報告

## 全社員共通のルール

- 前の担当の出力が揃うまで、次の担当は動かない
- 自分の担当範囲以外の仕事をしない
- 「要修正」の差し戻しは最大3回まで。
　3回で通らなければ、その記事は破棄して理由を報告する(ファイルは消さず、報告に「破棄」と書く)
- 入力ファイルにない数字(単価・承認率・実績・効果)を作らない。分からなければ「不明」
- 本人の体験は `inputs/experience.md` に書かれたものだけ。体験を創作しない

## 絶対に守ること

- 公開前に必ず検品担当を通す
- 検品担当の判定を、執筆担当が覆さない
- 人間の承認なしに外部へ投稿しない(このフォルダから外部への投稿・送信は一切しない)
- `inputs/` のファイルを書き換えない・消さない
- ASPのID・パスワード・APIキーをファイルに書かない
