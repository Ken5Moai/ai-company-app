# 運用ルール(買う前ノート / Claude Code 版)

星2〜3のレビューを「買う前に知っておきたかったこと」記事にする。
**書く役と落とす役を分け、公開は人が押印してから自分の手で行う。**

## 1本ぶんの流れ

入力は `inputs/reviews/<商品スラッグ>.md`(テンプレートは `inputs/reviews/_template.md`)。
日付は `YYYY-MM-DD`、スラッグは英小文字とハイフン(例 `rx-1-robot`)。

1. **researcher** サブエージェント:`inputs/` を読み、条件に合う候補を選ぶ
   → `output/research/<日付>.md`
2. **planner** サブエージェント:選ばれた1商品のレビューから「買う前に知りたかったこと」5つと見出し構成を作る
   → `output/plan/<日付>_<スラッグ>.md`
3. **writer** サブエージェント:設計図から記事を書く
   → `output/draft/<日付>_<スラッグ>.md`
4. 機械チェック:`node scripts/check.mjs output/draft/<ファイル> --reviews inputs/reviews/<スラッグ>.md`
   (未使用の商品なら `--unused` を付ける。使ったことがあれば付けない)
5. **checker** サブエージェント:記事と機械チェックの結果を読んで判定
   → `output/check/<日付>_<スラッグ>.md`(1行目は `判定: 公開可|要修正|人間確認`)
6. 判定ごとの扱い
   - **要修正** → writer に「checker の指摘箇所だけ直す」よう差し戻し、4〜5をやり直す。**差し戻しは2回まで**。
     2回で通らなければその記事は見送り、理由を報告する
   - **人間確認** → `output/check/` に理由を残し、人に返す。自動で公開側に進めない
   - **公開可**(かつ機械チェックの NG が0件)→ `output/final/<日付>_<スラッグ>.md` に写す
7. 最後に「本日の記事 N 本、押印待ち」と、各記事の判定・差し戻し回数・人間確認の理由を報告する

## 全員共通のルール

- 前の担当の出力ファイルが揃うまで、次の担当は動かない
- 自分の担当範囲以外の仕事をしない(調べる人は書かない、書く人は採点しない、落とす人は書き直さない)
- 入力にない数字・仕様・承認率・報酬額を作らない。分からなければ「不明」と書く
- `rules/ng-expressions.md` と `rules/brake.md` に従う

## 絶対に守ること

- 公開前に必ず checker と機械チェックを通す
- checker の判定を writer が覆さない
- **外部への投稿・送信・ASP管理画面の操作は一切しない**(公開は人が自分の手で行う)
- `inputs/` のファイルを書き換えない・消さない。`output/` は追記のみ(上書きが必要なら人に確認)
- APIキー・ASPのID/パスワードをファイルに書かない
